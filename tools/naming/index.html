语法

连接符

  • =模糊匹配，包含关键词
  • ==精确匹配，全值相等
  • !=排除该模糊条件
  • &&与（空白等价，可连写）
  • - !排除，可作用于任意条件

字段

catcat=="craft"职能分类（与下方筛选等价）

Rust Workspace 改名清单

以 Nisaba 为例的完整迁移步骤。不要只做全局替换——下面这些位置必须手动确认。

  1. 1
    先查占用

    在 crates.io 与 GitHub 搜索目标名,确认没有被同类工具占用:cargo search nisaba · cargo search misharu

  2. 2
    全局替换前先预览

    用 git grep -n -e 'Shushinak' -e 'shushinak' -e 'SHUSHINAK' 列出所有命中,确认没有遗漏大小写变体,再执行 perl -pi -e 批量替换。

  3. 3
    重命名目录

    用 git mv 而非 mv,保留历史:crates/shushinak-core → crates/nisaba-core,其余四个 crate 同理。

  4. 4
    检查 Cargo.toml

    手动确认 [workspace] members、[package] name、[lib] name、[[bin]] name,以及所有 path 依赖的相对路径。

  5. 5
    修正代码引用

    use shushinak_core 必须变成 use nisaba_core。Rust 的 crate 名用连字符、lib 名用下划线,两者都要改。

  6. 6
    外围文件

    README.md、docs/PRD.md、justfile、CI 配置、Dockerfile、.env.example、MCP 客户端配置、badge 链接。

  7. 7
    重新构建验证

    cargo clean && cargo build --workspace && cargo test --workspace,最后跑一遍 just check 本地门禁。

兼容性雷区
  • 审计哈希链:如果 chain 里用了 "shushinak" 作为 domain separator,改名会让旧链全部验证失败。改成中性常量 AUDIT_CHAIN_V1,或提供迁移工具。
  • MCP 工具名:已暴露给 Agent 的 tool 名一旦改动,旧配置全部失效。建议新旧双注册,旧名打弃用警告。
  • 环境变量:NISABA_* 优先读取,回退到 SHUSHINAK_* 并打印警告。
  • 配置目录:启动时若 ~/.config/nisaba 不存在且旧目录存在,自动迁移或复制。
  • crates.io:已发布的 crate 无法改名,只能发一个弃用版本,README 指向新 crate。
  • GitHub:仓库改名后旧 URL 会 302 重定向,但 CI、badge、Cargo.toml 里的 repository 字段仍需更新。
